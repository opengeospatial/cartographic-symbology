[[req-coverage-color-channels]]
===== Symbolizer `colorChannels` property

[requirement]
====
[%metadata]
identifier:: /req/coverage/color-channels
part:: An Encoding SHALL support defining a `colorChannels` Symbolizer property as a Color object.
part:: A Renderer SHALL support portraying each coverage cell with the red, green and blue components resolved from the `colorChannels` property for that cell, each in the range 0 to 1.
====

[[req-coverage-single-channel]]
===== Symbolizer `singleChannel` property

[requirement]
====
[%metadata]
identifier:: /req/coverage/single-channel
part:: An Encoding SHALL support defining a `singleChannel` Symbolizer property as a float.
part:: A Renderer SHALL support using the value resolved from the `singleChannel` property for each coverage cell as the input value to the `colorMap` and `opacityMap` properties.
part:: A Renderer SHALL support portraying each coverage cell over the area of that cell.
part:: A Renderer SHALL support portraying each cell of a variable that is not continuous (for example a land cover classification) with the color and opacity mapped from that cell's own value, without interpolating between the values of neighbouring cells.
====

[[per-coverage-interpolation]]
[permission]
====
[%metadata]
identifier:: /per/coverage/interpolation
part:: A Renderer MAY interpolate between the values of neighbouring cells of a continuous variable.
part:: A Renderer MAY portray a coverage from overviews, levels of detail, tiles or DGGS zones that combine several cells, for example where one pixel of the map covers several cells.
====

NOTE: The method of portraying cells on the map is not prescribed: a coverage can be drawn on a 2D map or draped on 3D terrain, and from several levels of detail. Whether a variable is continuous can come from the logical schema of the data, for example `"x-ogc-variableType": "continuous"`, or be implied by its `x-ogc-definition` or `x-ogc-unit`, however that information reaches the Renderer. Where nothing indicates whether a variable is continuous, this Standard does not require a behavior; a Renderer can assume that it may interpolate, preferably with a way for users to control it.

[[req-coverage-color-map]]
===== Symbolizer `colorMap` property

[requirement]
====
[%metadata]
identifier:: /req/coverage/color-map
part:: An Encoding SHALL support defining a `colorMap` Symbolizer property as an array of `value` (float) and `color` (Color) pairs which can be tagged with a `name`.
part:: A Renderer SHALL support portraying each coverage cell with the color mapped from its `singleChannel` value by the `colorMap`, using the color of an entry for a value equal to that entry's `value`, interpolating between the colors of the two closest entries for other values within the range of the map, and using the color of the first or last entry for values outside the range of the map.
====

[[rec-coverage-map-interpolation]]
[recommendation]
====
[%metadata]
identifier:: /rec/coverage/map-interpolation
part:: A Renderer SHOULD interpolate the colors of a `colorMap` and the opacities of an `opacityMap` so that the result lies between those of the two closest entries.
====

NOTE: The interpolation method is not specified: linear interpolation, or a smoother one, can be used. Linear interpolation, easing between the two closest entries and monotone cubic interpolation all keep the result between those entries, while a parabola fitted through three neighbouring entries can overshoot them. When all values of a coverage are equal to entries of the map (e.g., integer class codes), the cells take exactly the colors or opacities of those entries.

[[per-coverage-linear-light]]
[permission]
====
[%metadata]
identifier:: /per/coverage/linear-light
part:: A Renderer MAY convert the sRGB colors of a `colorMap` to linear light, interpolate between them there, and convert the result back to sRGB for output.
====

NOTE: A `colorMap` does not define stepped classes for continuous values (e.g., one color for all values from 0 to 10). Such classes can be written with chained conditional expressions using relational operators, e.g. `colorChannels: B04 < 10 ? green : (B04 < 20 ? yellow : red)`.
