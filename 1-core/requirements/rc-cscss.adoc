==== Cartographic Symbology Cascading Style Sheets

[[rc-table-cscss]]

[requirements_class]
.Cascading Style Sheets
====
[%metadata]
identifier:: http://www.opengis.net/spec/cartosym-1/2.0/req/cscss
inherit:: http://www.opengis.net/spec/cartosym-1/2.0/req/core
subject:: Style encodings and Renderers
====

[[req-cscss-grammar]]
===== Grammar

[requirement]
====
[%metadata]
identifier:: /req/cscss/grammar
part:: A style encoded as CartoSym-CSS SHALL conform to the BNF grammar definition of this requirements class.
part:: A Renderer SHALL support parsing styles encoded as CartoSym-CSS.
====

[[req-cscss-rules]]
===== Styling rules

[requirement]
====
[%metadata]
identifier:: /req/cscss/rules
part:: An Encoding SHALL support encoding a style as a sequence of styling rules, each consisting of zero or more selectors, an optional `.name`, symbolizer property assignments and nested rules enclosed within `{` `}`.
part:: An Encoding SHALL support assigning a value to a member of an object property (using `.`) or to an element of an array property (using `[` `]`), overriding only that portion of the property.
part:: A Renderer SHALL support symbolizer properties set further down in rules overriding those set by rules at the same level appearing earlier, and properties set in nested rules overriding those set in the parent rule.
====

[[req-cscss-selectors]]
===== Selectors

[requirement]
====
[%metadata]
identifier:: /req/cscss/selectors
part:: An Encoding SHALL support defining selectors either as expressions enclosed within `[` `]`, or as a short-hand data layer name.
part:: A Renderer SHALL support combining multiple expression selectors of a rule with a logical AND, combining multiple data layer name selectors with a logical OR, and combining those two groups with a logical AND.
====

[[req-cscss-expressions]]
===== Expressions

[requirement]
====
[%metadata]
identifier:: /req/cscss/expressions
part:: An Encoding SHALL encode expressions using CQL2-Text, extended with instance expressions, tuples, units of measure, conditional expressions and enumeration values as specified in this requirements class.
part:: A Renderer SHALL support evaluating CQL2-Text expressions (including WKT geometry) used directly as a selector or symbolizer parameter value.
====

[[req-cscss-include]]
===== Including style sheets

[requirement]
====
[%metadata]
identifier:: /req/cscss/include
part:: An Encoding SHALL support including another style sheet using the `.include` directive followed by a relative path enclosed within single quotes.
part:: A Renderer SHALL support replacing an `.include` directive by the content of the referenced style sheet, recursively, before interpreting the style.
====

[[req-cscss-comments]]
===== Comments

[requirement]
====
[%metadata]
identifier:: /req/cscss/comments
part:: An Encoding SHALL support C-style multi-line comments (between `/\*` and `*/`) and C++-style single-line comments (starting with `//`).
part:: A Renderer SHALL support ignoring comments when interpreting a style sheet.
====

[[req-cscss-variables]]
===== Variables

[requirement]
====
[%metadata]
identifier:: /req/cscss/variables
part:: An Encoding supporting the <<rc-variables,Variables>> requirements class SHALL define variables before the styling rules using the syntax `@<identifier> = <expression>;`, and reference them as an expression using `@<identifier>`.
====
