[[req-json-schema]]
===== JSON Schema

[requirement]
====
[%metadata]
identifier:: /req/json/schema
part:: A Producer SHALL generate CartoSym-JSON which validates against the CartoSym-JSON JSON Schema defined in this requirements class.
part:: A Consumer SHALL support parsing styles encoded as CartoSym-JSON.
====

[[req-json-expressions]]
===== Expressions

[requirement]
====
[%metadata]
identifier:: /req/json/expressions
part:: A Producer SHALL encode Selector and Symbolizer Parameter Value expressions based on the CQL2-JSON encoding, extended as specified by the JSON Schema to cover expressions which do not evaluate to a boolean value.
part:: A Producer SHALL encode the `isNot`, `notIn`, `notBetween` and `notLike` operators as a `not` operation whose only argument is the corresponding `isNull`, `in`, `between` or `like` operation.
====

NOTE: As in CQL2-JSON, the JSON Schema has no operation for the negated operators. For example, `name not like 'a%'` is encoded as `{ "op": "not", "args": [ { "op": "like", "args": [ { "property": "name" }, "a%" ] } ] }`, the same as `not (name like 'a%')`. When such an expression is written in CartoSym-CSS, the negated operator (`name not like 'a%'`) is the more readable form.

[[req-json-partial-update]]
===== Partial updates of object properties

[requirement]
====
[%metadata]
identifier:: /req/json/partial-update
part:: A Consumer SHALL support parsing a partial update of an object property, represented by an object containing only the modified properties, with an `alter` property set to `true`.
part:: A Renderer SHALL support preserving the values of the properties not specified in an object whose `alter` property is `true`, as set by earlier rules or by default values.
====

[[req-json-array-element-update]]
===== Updates of array elements

[requirement]
====
[%metadata]
identifier:: /req/json/array-element-update
part:: A Consumer SHALL support parsing an update to a single element of an array property, represented by an object with an `index` property set to the zero-based index of the array element, and a `value` property set to the new value of that element.
part:: A Renderer SHALL support updating only the array element identified by `index`, preserving the other elements of the array.
====

[[req-json-dot-size-color]]
===== Dot `size` and `color`

[requirement]
====
[%metadata]
identifier:: /req/json/dot-size-color
part:: A Producer SHALL NOT set both `size` and `stroke.width`, nor both `color` and `stroke.color`, for the same Dot within a single styling rule.
====

NOTE: The `size` and `color` of a Dot are the same values as the `width` and `color` of its stroke, and the value set last applies. The members of a JSON object have no order (RFC 8259), so within one styling rule there is no last value. Setting `stroke.width` in one styling rule and `size` in a later one is valid, even though both refer to the same Dot of the same Marker or Label: the value set by the later rule applies, as in CartoSym-CSS.

[[req-json-variables]]
===== Variables

[requirement]
====
[%metadata]
identifier:: /req/json/variables
part:: A Producer supporting the <<rc-variables,Variables>> requirements class SHALL encode variables as members of a top-level `$variables` object, referenced using a JSON Pointer within a `$ref` property (e.g., `{ "$ref": "#/$variables/myVariable" }`).
====

[[req-json-include]]
===== Including style sheets

[requirement]
====
[%metadata]
identifier:: /req/json/include
part:: A Consumer SHALL support parsing an `$include` property in the top-level object, specified as either a single relative file path string or an array of relative file path strings, which includes base style sheets.
part:: A Renderer SHALL support considering the styling rules of included style sheets before the styling rules defined by the including file.
part:: A Renderer SHALL support including style sheets encoded as CartoSym-JSON.
====

NOTE: A style that includes a style sheet in another encoding is not guaranteed to work with all implementations.
