[[req-labels-label]]
===== Symbolizer `label` property

[requirement]
====
[%metadata]
identifier:: /req/labels/label
part:: An Encoding SHALL support defining a `label` Symbolizer property as a Label, which is a MultiGraphic that can contain multiple graphical elements.
part:: A Renderer SHALL support drawing the graphical elements of the labels as a separate pass on top of all styled vector features and coverages.
====

[[rec-labels-overlap]]
[recommendation]
====
[%metadata]
identifier:: /rec/labels/overlap
part:: A Renderer SHOULD omit labels which cannot be placed without overlapping other labels, unless a property of the Symbolizer allows the overlap.
====

NOTE: A Marker's graphical elements are drawn at every place where the Marker applies, even where they overlap, as in the left panel of <<fig-example-labels-label>>. A label is by default left out where it would overlap another label (`/rec/labels/overlap`), and `priority` decides which of two conflicting labels is placed (`/req/labels/placement`). Which of two conflicting labels of the same `priority` is left out may differ between Renderers.

NOTE: Whether labels that would extend beyond the edges of the map are placed is left to the Renderer, for example as a configuration option, considering use cases such as rendering a static map, a dynamic map or map tiles.

[[req-labels-placement]]
===== Label `placement` property

[requirement]
====
[%metadata]
identifier:: /req/labels/placement
part:: An Encoding SHALL support defining a `placement` Label property as a LabelPlacement object including a `priority`, a `minSpacing` and a `maxSpacing`.
part:: A Renderer SHALL support placing labels so that a label with a higher `priority` is placed in preference to a conflicting label with a lower `priority`.
part:: A Renderer SHALL support repeating a label so that the distance between repetitions of that label is at least `minSpacing` and, where space allows, at most `maxSpacing`, both in pixels unless qualified with another unit (<<graphical-units-of-measure,Graphical Units of Measure>>).
part:: A Renderer SHALL support treating as repetitions of a label all labels with the same content from the same data layer (so that a road split into several features is labelled as one), and measuring the distance between repetitions on the map between their positions.
====

[[req-labels-line]]
===== Labels along lines

[requirement]
====
[%metadata]
identifier:: /req/labels/line
part:: A Renderer SHALL support placing a label on a line geometry along that line, with each Text element of the label following the curve of the line, and each other graphical element turned to the direction of the line where it is placed.
part:: A Renderer SHALL support placing a label along a line so that it reads from left to right and is never upside down, whatever the direction in which the line is defined.
part:: A Renderer SHALL support joining, before placing their labels, the line geometries of a data layer that have the same label and meet at their end points, so that a line split into several features (such as a road) is labelled along the joined line.
part:: A Renderer SHALL support placing all the graphical elements of a label along a line together, with the `x` of each element's `position` measured along the line in the direction in which the label reads, and its `y` perpendicular to the line, positive towards the bottom of the label, as a positive `y` is downwards for a label placed at a point (`/req/vector/graphics`).
====

[[rec-labels-line]]
[recommendation]
====
[%metadata]
identifier:: /rec/labels/line
part:: A Renderer SHOULD omit a label along a line where the line is shorter than the label.
====

NOTE: How sharp a bend a label along a line may follow is left to the Renderer. This requirement does not turn labels on point and polygon geometries.
