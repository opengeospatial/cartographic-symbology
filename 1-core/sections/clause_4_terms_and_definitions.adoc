== Terms and definitions

For the purposes of this document, the following terms and definitions apply.

This document used the terms defined in Policy Directive 492, which is based on the ISO/IEC Directives, Part 2, Rules for the structure and drafting of International Standards. In particular, the word “shall” (not “must”) is the verb form used to indicate a requirement to be strictly followed to conform to this standard and OGC documents do not use the equivalent phrases in the ISO/IEC Directives, Part 2.

This document also uses terms defined in the OGC Standard for Modular specifications (OGC 08-131r3), also known as the ‘ModSpec’. The definitions of terms such as standard, specification, requirement, and conformance test are provided in the ModSpec.

For the purposes of this document, the following additional terms and definitions apply.

=== Portrayal
Presentation of information to humans (Note 1 to entry: Within the scope of this International Standard, portrayal is restricted to the portrayal of geographic information). [SOURCE: ISO 19117:2012, 4.20]

=== Layer
Abstraction of reality specified by a geographic data model (feature, coverage…​). A layer may be represented using a set of symbols (Style). A layer contributes to a single geographic subject and may be a theme.

=== Data layer
The features of one feature type, or the cells of one coverage, that a style addresses by one identifier.

NOTE: An OGC API collection is one data layer, or one data layer per feature type when its features have several types. A feature's type is given by the property with `"x-ogc-role": "type"` in the logical schema (https://docs.ogc.org/is/23-058r2/23-058r2.html[OGC API - Features - Part 5 / OGC API - Common - Part 3: Schemas]), or by the `featureType` of https://docs.ogc.org/is/21-045r1/21-045r1.html[JSON-FG]. Otherwise, when the `featureTypes` of the collection description (https://docs.ogc.org/is/20-024/20-024.html[OGC API - Common - Part 2]) lists exactly one type, all the features of the collection have that type. Otherwise all the features of the collection, or of the file, are one data layer, and a collection's identifier serves as its feature type.

NOTE: The features of one data layer can have different geometry types, such as points, lines and polygons. A style tells them apart in its selectors.

=== Style
A sequence of rules of symbolizing instructions to be applied by a rendering engine on one or more features and/or coverages.

=== Rendering engine
Automated process that produces graphics using a pipeline of layers and styles as inputs.

=== Consumer
Application taking a style as input, such as a rendering engine or a transcoder.

=== Producer
Application generating a style, such as a style editor or a transcoder.

=== Render
Conversion of digital graphics data into visual form (EXAMPLE Generation of an image on a video display) [SOURCE: ISO 19117:2012, 4.27]
